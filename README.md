# Guardians Telegram bot

Развёртывание на Vercel с облачными БД и Redis: [VERCEL.md](VERCEL.md).

Самостоятельный репозиторий aiogram. Связь с API — HTTP и `X-API-Key`.

## Настройка

Скопируйте `.env.example` в `.env`, если файла ещё нет. Укажите `BOT_TOKEN`,
`BACKEND_BASE_URL` (например `http://127.0.0.1:8000`, без `/api/v1`),
`BACKEND_API_TOKEN` (значение `BOT_API_KEY` API), `REDIS_URL`.
В Compose бот использует отдельный Redis. Для локального запуска допустим Redis API:
FSM имеет отдельный префикс `guardians:bot:fsm`, данные SOS принадлежат API.
В текущем локальном `.env` уже настроен существующий облачный Redis.

## Docker

Сначала выполните `docker compose up -d --build --wait` в репозитории API,
затем ту же команду в этом репозитории. Compose бота подключается к сети
`guardians-integration`, используя адрес `http://guardians-api:8000`.
Пути к соседнему репозиторию не используются. Для удалённого API запускайте
бота локально с его HTTP-адресом либо настройте Compose под свою сеть.
Логи: `docker compose logs -f bot`. Остановка: `docker compose down`.

## Windows

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
docker compose up -d redis
.\run.ps1
```

API должен быть запущен. При использовании `.env.example` локальный Redis бота
доступен на порту 6380; для облачного `REDIS_URL` контейнер Redis не требуется.
`python main.py` и `python -m app.main` запускают одну реализацию.
Настройки `.env` загружаются относительно репозитория.

## Проверка в Telegram

1. `/register`: имя и телефон; `/profile`: сохранённый профиль.
2. `/add_contact`: имя, телефон и Telegram ID (или `-`, только телефон).
   Получатель должен предварительно открыть бота и нажать `/start`.
3. «🚨 СОС / Помощь»: подтвердить и отправить геопозицию.
4. Бот показывает число доставленных Telegram-уведомлений. `/cancel_sos` отменяет вызов.

Телефон сам по себе не позволяет отправить Telegram-уведомление. SMS и вызова 112 нет.
Доставка выполняется ботом после регистрации SOS, без постоянной очереди и
автоматического повтора при падении процесса. API хранит вызов независимо от доставки.

Проверки: `.\.venv\Scripts\python.exe -m unittest discover -s tests`.

## Версии и зависимости

Python 3.13 используется локально, в Docker и Vercel. `.python-version` задаёт
ветку Python; Docker использует `python:3.13-slim-bookworm`. Устанавливайте актуальное
исправление Python 3.13. Прямые зависимости закреплены в `requirements.txt`;
транзитивные зависимости разрешает pip — это не полный lock-файл.
`pyproject.toml` содержит только точку входа Vercel, список зависимостей не дублируется.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Compose предназначен для отдельного локального стека. На Vercel используются
облачные PostgreSQL/Redis из переменных окружения; Compose там не запускается.

## Патруль и помощь волонтёров

Регистрация `/register` предлагает две роли: «Нужна помощь» и «Волонтёр».
Заявитель создаёт SOS кнопкой и отправляет своё местоположение. Волонтёр нажимает
«Начать патруль» и включает Telegram Live Location через скрепку → Геопозиция →
Транслировать геопозицию. Кнопка отправки текущей точки передаёт только разовую
геопозицию: её нужно повторять вручную. Частоту Live Location определяет Telegram,
бот не может включать GPS или опрашивать телефон по расписанию.

API обновляет Redis GEO на каждом новом `message`/`edited_message`. По умолчанию
координаты актуальны 5 минут, патруль длится до 8 часов. Без свежих обновлений
волонтёр исключается из поиска. «Статус патруля» показывает актуальность. Остановка
патруля удаляет точку; запоздалые сообщения не включают выключенный патруль.
Остановка Live Location исключает текущую точку; для возвращения нужна новая.

При создании SOS все свободные волонтёры с актуальными координатами в радиусе
3 км получают сообщение с кнопкой «Принять вызов». Доверенные контакты также
получают сообщение. Заявитель видит количество успешно доставленных уведомлений.
Доставка Telegram может завершиться ошибкой (например, бот заблокирован);
постоянной очереди повторной доставки сейчас нет.

Первый волонтёр, принявший вызов, закрепляется за ним. Конкурирующий отклик
получает отказ. Статус хранится в PostgreSQL: `ACTIVE → ACCEPTED → RESOLVED`.
Занятый волонтёр не получает новые предложения. Завершить принятый вызов кнопкой
«Завершён — помощь оказана» может только заявитель. «Мой вызов» (`/call`)
восстанавливает управление из БД даже после перезапуска бота или истечения Redis.

Настройки API: `VOLUNTEER_RADIUS_KM=3`, `VOLUNTEER_LOCATION_TTL_SECONDS=300`,
`PATROL_TTL_SECONDS=28800`. Для этой функции не нужны cron или фоновый процесс.
